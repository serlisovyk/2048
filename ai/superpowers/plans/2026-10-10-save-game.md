## 1. Where each part lives (`ai/rules/oop.md`)

| Layer      | Class / file                 | Change                                                                                                                                                                                                      |
| ---------- | ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Model      | `game/Board.js`              | `restore(cells)` — validates size and tile values, copies the cells in, returns `true`/`false`; changes nothing on failure. The tile-value check is a private static helper.                                |
| Model      | `game/Game.js`               | `toState()` → `{ board, score, hasWon }` (copies); `restore(state)` → `true`/`false` — checks `score` and `hasWon`, delegates the board, rejects a board without moves. No storage, no `version` knowledge. |
| Storage    | `storage/SafeStorage.js`     | `getJson(key)` → parsed value or `null` (missing, blocked, or corrupted); `setJson(key, value)`; `remove(key)`. Generic — knows nothing about the game, never throws.                                       |
| Controller | `GameController.js`          | Use case: `start()` tries to restore, else starts new; save after a move; clear on game over and in `#startNewGame()`. Owns the envelope: adds and checks `version`.                                        |
| Constants  | `constants.js`               | `STORAGE_KEYS.SAVED_GAME = 'savedGame'`, `SAVED_GAME_VERSION = 1`.                                                                                                                                          |
| Other      | views, input, `main.js`, CSS | Unchanged. `main.js` already passes `SafeStorage` and `Game` to the controller; no new DOM lookups.                                                                                                         |

Why the split: the model knows what a legal board is, so it validates the board; the
format version is a persistence concern, so the controller (the use case that joins
model and storage) checks it; `SafeStorage` stays game-agnostic.

## 2. Controller flow

- `start()`: read the high score, then
  `saved?.version === SAVED_GAME_VERSION && game.restore(saved)`. If restored,
  render the board and the score (no dialog, `#isPausedAfterWin` stays `false`);
  otherwise `#startNewGame()`.
- `#startNewGame()`: clears the saved game first, so an invalid or old save is
  deleted and `New Game` starts from a clean slate.
- `requestMove()`: after a successful move, `result.isOver` → show game over and
  clear the save; otherwise save `{ version, ...game.toState() }`.
- `Continue` needs no change: the win already wrote `hasWon: true`.

## 4. Verification

- `yarn lint`, `yarn format:check`, `yarn build`, `yarn size` (budget: JS 8 kB gzip).
- Play in `yarn dev --port 5182 --strictPort`, desktop and mobile width, with the
  browser tools:
  - play a few moves, reload — board and score restored, `savedGame` in
    `localStorage` matches the screen;
  - `New Game` removes the key; one move writes it again;
  - craft a save one move away from game over, play the move, check the key is gone
    and the dialog shows, reload — new game;
  - craft a save with two `1024` tiles, win, `Continue`, reload — no win dialog;
    reload with the dialog still open — no dialog, `hasWon: true` stays;
  - corrupted JSON, wrong version, wrong board size, `1` / `3` / `-2` / string
    cells, negative / fractional score, non-boolean `hasWon`, a full board without
    moves — each starts a new game, deletes the key, no console errors;
  - blocked `localStorage` (a throwaway page that makes `window.localStorage` throw
    before the game script runs, deleted afterwards) — the game plays, no errors;
  - the high score still persists independently.
- Constants are never changed for testing; the crafted saves cover win and game
  over.
