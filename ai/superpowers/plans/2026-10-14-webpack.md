## 1. Choices

### The config

One `webpack.config.js` (ESM, the package is `"type": "module"`) exporting a function of `(env, { mode })`: dev and production
differ only in file names (no hashes in dev, so CSS can hot-update), the minimizers and the HTML minification.

- `entry: src/scripts/main.js`, which already imports `styles/main.css`. `output.path` is `dist`, `publicPath: '/'` (the absolute
  `/assets/…` URLs Vite wrote), `clean: true`, names `assets/[name]-[contenthash:8]` for JS, CSS and assets, so the
  `size-limit` globs keep matching.
- `target: ['web', 'es2020']` only tells Webpack what syntax its own wrapper may use; our modules are not touched (no Babel).
- `copy-webpack-plugin` copies `public/` to the root of `dist/`.

### JS

`terser-webpack-plugin` with the options of today's Vite build (`drop_console`, `passes: 2`, no comments) and
`extractComments: false` so no `*.LICENSE.txt` appears next to the bundle. Production mode already concatenates modules
(scope hoisting) and drops source maps. The output is a classic IIFE, so the script is `defer` (it runs after parsing, from
`<head>`), not `type="module"`: a non-module bundle in a module script would only say something untrue. Rejected:
`experiments.outputModule` (experimental, and dev-server HMR with it is not settled).

### CSS

`MiniCssExtractPlugin.loader`, `css-loader` (`importLoaders: 1`, it follows `@import` and `url()`), `lightningcss-loader`
(nesting, `<=` ranges and prefixes for the targets). `LightningCssMinifyPlugin` from the same package minifies the one
extracted file in production (the loader cannot minify), with the same targets, so rules are merged across the files as
esbuild did.

`lightningcss-loader` takes the targets as browserslist **queries** (it runs them through the `browserslist` package; with no
list it would read a `browserslist` config or the defaults). The config therefore keeps the object
`{ chrome: 107, edge: 107, firefox: 104, safari: 16 }` and derives `['chrome 107', …]` from it. That is a list in the config,
not a `browserslist` field or file.

**Prefixes are not "the same" as Autoprefixer's, by design.** Autoprefixer's defaults reach back to Firefox ESR and old Safari:
the old build had `-moz-user-select`, `-moz-column-gap` and `width: -moz-min-content`, which Firefox 104 does not need. With the
explicit targets the prefix that stays is `-webkit-user-select` (Safari 16). The record says the targets are the single list.

### HTML

`html-loader` (`minimize: false`; the minifier is `html-webpack-plugin`'s) turns the `favicon.svg` link and the font preload into
module requests. The font is the same module as the `@font-face` `url()`, so both get one hashed URL and the browser makes one
request; the favicon is hashed into `assets/` as it was under Vite. The `<script type="module" src>` line leaves the template:
the entry is configured, and `html-webpack-plugin` injects the tag. `minify` is the object of the old plugin, production only.
The meta `description` says "and Vite"; it is metadata about the stack (`ai/rules/assets-performance.md`), so it says Webpack.

### The theme head script

A class `InlineThemeScriptPlugin` in the config taps `afterTemplateExecution`, reads `themeHead.js`, minifies it with terser and
puts it right after `<head>`, before `<meta charset>`, as today. It throws if the template has no `<head>` (a silent miss would
be a theme flash), and adds the file to the watched files, so an edit rebuilds the page.

### Dev and preview

`dev` is `webpack serve --mode development`; the port comes from `--port`. CSS is extracted in dev too (a render-blocking
`<link>`, no unstyled frame) and hot-updates; the modules have no accept handlers, so a script edit reloads the page, as under
Vite. `preview` is `sirv dist`; `--port` passes through.

### Vercel

`vercel.json` with `framework: null` (the "Other" preset), `installCommand: yarn install --frozen-lockfile`,
`buildCommand: yarn build`, `outputDirectory: dist`. Per the Vercel docs, `vercel.json` overrides the dashboard's settings for
every deployment, so a leftover Vite preset cannot pick another command. After the push the author checks the preview
deployment.

### Dependencies

Added (dev): `webpack`, `webpack-cli`, `webpack-dev-server`, `html-webpack-plugin`, `html-loader`, `css-loader`,
`mini-css-extract-plugin`, `lightningcss-loader`, `lightningcss` (the config imports `Features` from it), `terser-webpack-plugin`,
`copy-webpack-plugin`, `sirv-cli`. Removed: `vite`,
`postcss`, `autoprefixer`, `html-minifier-terser` (`html-webpack-plugin` brings its own). Kept: `terser` (the head script).
`webpack-dev-server` stays on 5: version 6 needs Node 22.15, the package's `engines` allows 20.19 and 22.13.

## 6. What building it found

- **The result.** Every screenshot of the Webpack build equals the Vite baseline to the pixel: 48 of 48 states, 52 of 52
  interaction states (hover, keyboard focus, reduced motion), and the record badge, in the production build; the 48 states
  again from `yarn dev`. The same fixtures rendered twice on the baseline were identical too, so a match means something.
  The font is one request, the console is empty in dev and in the build, and the page's first element in `<head>` is the
  inline theme script, set before the first paint for a saved light theme under a dark system and the other way round.
- **`lightningcss-loader` has no object for targets.** It takes browserslist queries and runs them through `browserslist`;
  without a list it would read a `browserslist` config or the defaults. The config keeps the object and derives the queries.
- **`color-scheme` made Lightning CSS add `--lightningcss-light` and `--lightningcss-dark` to both `:root` blocks**, twice
  (loader and minimizer), for a `light-dark()` polyfill the project does not use. `Features.LightDark` is excluded in both.
- **A head script edit did not reach the dev page.** `html-webpack-plugin` skips its hooks when the template and the assets
  did not change (`cache: true`), so the edit was ignored; and in hot mode an HTML-only rebuild reloads nothing. `cache: false`
  and `devServer.watchFiles` for the template and the script fix both (measured: the edit is on the page in about 110 ms).
- **The favicon vanished from the dev server after the first rebuild.** It is referenced only from the template, whose child
  compilation is cached on a CSS or JS edit, and `output.clean` removed it from the in-memory output (a 404 until the template
  changed). `clean` is on in production only; polled 250 times during edits before the change, 0 failures after.
- **`webpack-dev-server` logs a warning at each script edit** ("Cannot apply update", the modules accept no updates), so
  `client.logging` is `error`: the console stays empty, the overlay still shows build errors. CSS updates in place in about
  110 ms with the page kept; a script edit reloads the page, as it did under Vite.
- **What Lightning CSS rewrites, all equal in effect**: `rgba()` to 8-digit hex (the alpha is rounded to 8 bits, no pixel
  moved), colours in custom properties shortened (`--page-bg: #333333` is `#333`, so `ThemeView` now writes `#333` into the
  `theme-color` metas: the same colour), `0ms` to `0s` in a custom property, longhands merged into `grid-area` and `place-self`, adjacent rules with the same
  declarations joined, the `::view-transition-old(root), ::view-transition-new(root)` list split in two (a list with a
  pseudo-element that old browsers drop would be dropped whole), `@layer a, b;` shortened when `@layer a {…}` follows. Prefixes:
  `-webkit-user-select` stays, `-moz-user-select`, `-moz-column-gap` and `width: -moz-min-content` are gone (not needed from
  Firefox 104). A throwaway stylesheet with what MY-140 brings went through the real build: `@container` (with `>=`, `<`, a
  name, `cqw`/`cqi`), `@media (width >= …)` to `min-width`, `(width > …)` to `not (max-width: …)`, `(a <= width <= b)`, `:has()`,
  `@layer`, `@property`, `@view-transition`, `svh`, `lh`, `text-wrap`, `light-dark()` pass through or lower correctly.
- **Size and time** (Vite to Webpack): JS 8.19 to 7.90 kB gzip (23.6 kB raw, a single concatenated IIFE with no webpack
  runtime), CSS 4.10 to 4.01 kB, font 35.35 kB unchanged, `index.html` 9,011 to 8,982 bytes raw. The same six files, with
  the same layout and one favicon. A production build is about 0.9 s wall (0.53 s compile) against Vite's 1.1 s (0.43 s);
  a cold `webpack serve` answers the first request after 0.96 s (0.39 s compile) against Vite's 0.62 s (0.24 s).
- **`webpack-dev-server` 6 needs Node 22.15**, so the package is on 5; `yarn dev` without `--port` is on 8080, not Vite's 5173.
- **After MY-140 (rebased onto `895e6af`).** Two conflicts, both in docs (`ai/map.md`, `ai/rules/style.md`); `index.html` merged
  on its own (the GitHub link last, the statistics markup, no entry `<script>`). Against a fresh Vite build of `895e6af`: 112 of
  112 states at 8 viewports (the old four plus 1366×657, 1280×600, 667×375 and 768×1024, with 3×3 and 5×5 boards and the
  settings with the statistics tiles), 104 of 104 interaction states, and 112 of 112 from `yarn dev`, identical to the pixel;
  33 of 33 scenarios on the build and on dev. The built CSS keeps the same media conditions (`>=` to `min-width`, `<=` to
  `max-height` and `max-width`), the same `svh` and the same `--rows-height`, `--side-width` and `--cell-size` text; the landscape
  rules differ only in order and in `align-content` plus `justify-content` joined into `place-content`. JS 8.24 to 7.96 kB gzip,
  CSS 4.41 to 4.33 kB.
- **Not checked**: Safari and Firefox, the Vercel preview deployment (the author checks it after the push), a CI run on
  Linux. README still says Vite: it is MY-132's.

## 7. The config split (the author's follow-up)

One `webpack.config.js` of 165 lines was hard to read, so it is split into small parts, as in the author's other project
(`serlisovyk/Personal`). The output is untouched: every file of `dist/` has the same SHA-256 before and after.

| File                                         | Holds                                                                                  |
| -------------------------------------------- | -------------------------------------------------------------------------------------- |
| `webpack.config.js`                          | One line, re-exporting `webpack/config.js`.                                            |
| `webpack/config.js`                          | Reads `mode` once, assembles the config from the parts.                                |
| `webpack/paths.js`                           | The root, `src`, `dist`, `public`, the template, the entry and `themeHead.js`.         |
| `webpack/targets.js`                         | The browser versions, the Lightning CSS targets, the feature that is switched off.     |
| `webpack/parts/module-rules.js`              | `getModuleRules()`: `html-loader`, the CSS chain, the font and SVG assets.             |
| `webpack/parts/plugins.js`                   | `getPlugins({ isProduction, hashSuffix })`: HTML, CSS extract, copy, the theme plugin. |
| `webpack/parts/optimization.js`              | `getOptimization()`: terser and the Lightning CSS minimizer.                           |
| `webpack/parts/dev-server.js`                | `getDevServer()`.                                                                      |
| `webpack/plugins/InlineThemeScriptPlugin.js` | The plugin class, one class per file.                                                  |

- **No comments in the build config or the other root configs** (`ai/rules/style.md`). The four "why" comments of the old
  file moved to `2026-10-14-webpack-instead-of-vite.md` (the `light-dark()` exclusion, the kept attribute quotes, the dev
  server's `static: false`) and `2026-10-14-theme-head-script-html-plugin.md` (`cache: false`, `watchFiles`).
  `CSS_EXCLUDED_FEATURES` became `UNUSED_CSS_FEATURES`, so the name says why it is excluded. The other root configs
  (`eslint.config.js`, `.size-limit.json`, `.lintstagedrc.json`, `vercel.json`, `ci.yml`, `.husky/pre-commit`) had no comments.
- `hashSuffix` is computed once in `config.js` and passed to the parts that name files, so the literal is not repeated.
- `eslint.config.js` gives the Node globals to `webpack/**/*.js` as well as `*.config.js`; the OOP rules stay on
  `src/scripts/`.
