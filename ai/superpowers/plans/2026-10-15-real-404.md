# MY-143 — A real 404: the game page as `404.html`

Issue: MY-143 · Branch: `my-143-real-404` · No spec: the game does not change; a missing URL answers 404 with the game page.

Base is `main` at `af8a809`. `robots.txt` and `llms.txt` are served (`2026-10-15-crawl-files.md`), but the live site still
answers every missing path with `200 text/html` and `index.html` (`/definitely-not-here`, `/assets/`, `/foo/bar/baz.png`,
`/.well-known/ai-catalog.json`), so the Lighthouse ARD audit fails and crawlers see soft 404s.

## Author's decisions (2026-10-15, final)

- The dashboard is checked: CDN → Routing Rules is empty, the Framework Preset is "Other", and the Build Command override
  `vite build` is stale (the `buildCommand` in `vercel.json` wins). So the catch-all's origin is unknown.
- Fix it in the repo, not in the dashboard. No `routes` in `vercel.json` (the editor and the docs mark `handle` as
  deprecated) and no separate 404 page: the 404 response is the game itself.

## What the Vercel docs say

- A `404.html` in the output directory is served as the 404 page "when a route does not match any other static file", with
  no configuration ([custom 404 page](https://vercel.com/kb/guide/custom-404-page)). The hypothesis: the catch-all is what
  Vercel does when the output has no `404.html`. The docs do not say so, so a preview deployment is what proves it.
- `routes` stays the fallback only: it can be used next to the other keys, but `handle` is a deprecated route property
  and the schema marks that variant `deprecated`
  ([`vercel.json` → routes](https://vercel.com/docs/project-configuration/vercel-json#routes)). A rewrite cannot set a
  status, so it would answer `200`.

## Changes

1. `webpack/parts/plugins.js`: one `createPagePlugin({ filename, isProduction })` used twice, for `index.html` and
   `404.html`: the same template and options, so the pages are byte for byte equal. The entry chunk is shared, so the
   bundle is emitted once. `InlineThemeScriptPlugin` taps a hook of `html-webpack-plugin` for every page it builds, so
   the theme script is first in `<head>` of both; no change to it.
2. Asset URLs are absolute (`publicPath: '/'`), so the game plays at any path, `/foo/bar/baz` included.
3. No change to `vercel.json`, `.size-limit.json` (it globs `dist/assets/`) or the lint and format setup.
4. Docs: a new record (a missing path answers 404 with the game page; restates the crawler files and no ARD catalog; the
   fallback `routes` table as a note) that supersedes `2026-10-15-crawler-files-no-catch-all.md` (its `Status` line is the
   only edit); the rule in `ai/rules/assets-performance.md`; one line in `ai/map.md`; the records index.
