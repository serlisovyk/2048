# MY-113 — Save the current game in localStorage

Issue: MY-113 · Branch: `my-113-save-game` · Plan: `ai/superpowers/plans/2026-10-10-save-game.md`

Today a page reload or an accidentally closed tab drops the game in progress; only
the high score survives. This spec defines what the player sees and what is stored.

## Behavior

| Situation                                                    | Result                                                                     |
| ------------------------------------------------------------ | -------------------------------------------------------------------------- |
| Reload in the middle of a game                               | The board and the score come back as they were                             |
| Reload right after a game over                               | A new game starts; the finished game is gone                               |
| Saved data is corrupted JSON, an unknown version, or invalid | The data is ignored and deleted, a new game starts, nothing is logged      |
| `localStorage` is blocked or throws                          | The game works exactly as before, it just is not saved                     |
| Win, then `Continue`, then reload                            | The game continues; the win dialog is not shown again                      |
| Win dialog still open (no `Continue`), then reload           | The game continues without the dialog (the save has `hasWon: true`)        |
| `New Game` / `Restart Game`                                  | The saved game is deleted and a fresh game starts                          |
| A move that changed nothing                                  | Nothing is written                                                         |
| Fresh page, no move made yet, then reload                    | A new random game (the first save happens after the first successful move) |

The high score is stored separately under its own key, exactly as now.

## Saved-game format

Key `savedGame` (`STORAGE_KEYS.SAVED_GAME`), value is JSON:

```json
{
  "version": 1,
  "board": [
    [2, 0, 0, 4],
    [0, 0, 0, 0],
    [0, 8, 0, 0],
    [0, 0, 0, 2]
  ],
  "score": 36,
  "hasWon": false
}
```

- `version` — `SAVED_GAME_VERSION` (`constants.js`), currently `1`. A save with any
  other version is discarded.
- `board` — rows of tile values, `0` for an empty cell.
- `score` — the current score.
- `hasWon` — whether the win tile was already reached in this game.
- Version 1 has no `size` and no `winTile`: it always means a 4x4 board and the 2048
  target. The "Game modes" and "Win target" issues add those fields under a new
  version and keep loading version 1 as 4x4 / 2048.

## Validation on load

A saved game is restored only when all of these hold; otherwise it is deleted and a
new game starts:

- the stored text is valid JSON and an object;
- `version` equals `SAVED_GAME_VERSION`;
- `board` is `BOARD_SIZE` rows of `BOARD_SIZE` cells;
- every cell is `0` or a power of two from `2` up (integers only);
- `score` is a non-negative integer;
- `hasWon` is a boolean;
- the board still has a possible move — a finished game is never restored.

## Lifecycle

- **Written** after every successful move that does not end the game.
- **Deleted** when a move ends the game (game over), on `New Game` / `Restart Game`,
  and whenever a stored game fails validation on load.
- **Not stored**: a finished game. The player cannot get back to the game-over board
  by reloading.

## Notes

- Restoring does not replay spawn animations. The grid renders the restored tiles
  through the same path as any render, so they get the short merge pulse once on
  load (the known coupling tracked in MY-126, which reworks tile animations);
  `prefers-reduced-motion` already disables it.
- The "no dialog after reload" rule is deliberate: it keeps the restore path free of
  dialog state, and the win was already announced once.

## Out of scope

- Per-size or per-mode saves and the version-1 migration path (MY-128 and the "Win
  target" issue).
- Confirming `New Game` over an unfinished game (MY-115).
- Syncing the saved game between several open tabs (the last write wins).
