  control and turns it into a direction. It still only calls `onDirection`; whether

- `src/scripts/constants.js` — the key → direction mapping, in the block of
  `ARROW_KEY_DIRECTIONS` only (the storage-key block below it is being changed by

- No change to `main.js`: `KeyboardInput` keeps the same constructor and `bind()`,
  and keeps listening on `document`.

## Changes

### 1. Mapping — `constants.js`

Rename `ARROW_KEY_DIRECTIONS` to `KEY_CODE_DIRECTIONS` (it is no longer arrows
only, and it is keyed by `event.code`) and add the four letter keys:

```js
export const KEY_CODE_DIRECTIONS = Object.freeze({
  ArrowUp: DIRECTIONS.UP,
  ArrowDown: DIRECTIONS.DOWN,
  ArrowLeft: DIRECTIONS.LEFT,
  ArrowRight: DIRECTIONS.RIGHT,
  KeyW: DIRECTIONS.UP,
  KeyS: DIRECTIONS.DOWN,
  KeyA: DIRECTIONS.LEFT,
  KeyD: DIRECTIONS.RIGHT,
})
```

The arrow `event.code` values equal the old `event.key` names, so the arrow entries
do not change.

### 2. Handler — `KeyboardInput.js`

```js
#handleKeydown = (event) => {
  if (!Object.hasOwn(KEY_CODE_DIRECTIONS, event.code)) return
  if (KeyboardInput.#hasCommandModifier(event)) return
  if (KeyboardInput.#isInsideNonGameContext(event.target)) return

  event.preventDefault()
  this.#onDirection(KEY_CODE_DIRECTIONS[event.code])
}
```

- `static #hasCommandModifier(event)` — `ctrlKey || metaKey || altKey`.
- `static #isInsideNonGameContext(target)` — false when `target` is not an
  `Element` (a synthetic event dispatched on `document`); otherwise
  `target.isContentEditable` or `target.closest(selector) !== null`.
- The selector is a private static field of `KeyboardInput`
  (`'input, textarea, select, dialog[open], [role="dialog"]'`): it is used by this
  class only, so it is not a shared constant. `closest()` on the event target needs
  no `document.querySelector`, so the OOP lint rule is not in play.
- Order: the cheap `code` lookup first, so unrelated keys cost one hash lookup.
