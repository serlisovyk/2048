# MY-123 — Light/dark theme: tokens, a switch, a view-transition reveal, `theme-color` (spec)

Issue: MY-123 · Branch: `my-123-theme` · Plan: `ai/superpowers/plans/2026-10-10-theme.md`

## Goal

The game gets a light theme next to today's dark one. The player switches between them with
an icon button in the header; the new theme spreads from that button as a circle where the
browser supports it. The choice survives a reload, the first visit follows the system
setting, and the page never paints in the wrong theme first. The dark theme looks exactly as
it does today.

## What is wrong today

- There is one dark theme, and its colours are written as literals across six CSS files
  (`#333333`, `#444444`, `#f0f0f0`, `rgba(...)`, about 40 lines), so a second theme cannot be
  added without editing every selector.
- The page ignores `prefers-color-scheme`. A player who uses a light system gets a dark game
  with no way out.
- The browser's address bar colour (`theme-color`) is fixed at `#333333`.

## Behavior

### Which theme is shown

- With no saved choice, the theme follows the system: light when the system asks for light,
  dark otherwise (including a browser that does not know the setting, so it stays as today).
- A saved choice wins over the system. The only way to save one is the toggle button.
- While there is no saved choice and the page is open, a change of the system setting
  changes the theme at once, without the circle animation.
- Once the player has used the toggle, the system setting is ignored until site data is
  cleared. There is no "follow the system" option in the UI: the switch has two states.
- The theme is applied before the first paint, so a reload in the light theme never flashes
  the dark one (and the other way round). If storage is blocked or holds garbage, the system
  setting decides and nothing breaks.

### The toggle

- A `toolbar-button` in the header toolbar, after `New Game`: 44px, the same look as the
  other toolbar buttons, with the same focus ring.
- It shows a sun while the dark theme is on and a moon while the light theme is on: the icon
  is the theme the button switches to.
- Its `aria-label` and `title` are the same text and name the action: `Switch to light theme`
  in the dark theme, `Switch to dark theme` in the light theme. It has no `aria-pressed`; the
  label already changes.
- A click or `Enter` / `Space` switches the theme and saves the choice. Focus stays on the
  button.

### The reveal animation

- In a browser with the View Transitions API, the new theme spreads from the centre of the
  toggle button as a growing circle over about 0.5s and covers the whole window. A keyboard
  activation starts it from the same place: it uses the button's position, not the pointer's.
- Without the API, or with `prefers-reduced-motion: reduce`, the theme changes at once, with
  no animation and no error.
- A second switch while the first is still running replaces it; the last choice wins and
  nothing is left half-switched.

### Browser chrome

- `meta theme-color` always holds the page colour of the current theme (`#333333` dark,
  `#f4efe6` light), so the address bar on a phone matches the page. It changes together with
  the theme, including after a system-driven change.

### The light theme

- Every colour comes from a token; dark values are exactly today's. The light palette is
  warm paper and ink: page `#f4efe6`, ink `#2e2620` (the colour the dark tile text already
  uses), white-ish score boxes and toolbar buttons, a taupe board.
- The tile colours do not change; only their shadow and the 2048 glow get light values. The
  number on every tile keeps at least 3:1 against both ends of its gradient.
- The gold of the score numbers and of the `+N` pop becomes a darker gold in the light theme
  so it can be read (at least 4.5:1). The logo tile stays gold, and so does the "New record!"
  badge (a gold pill with dark text, 8.96:1) in both themes; only its shadow changes.
- The confirmation dialog follows the theme (a light card with dark text and a dark primary
  button in the light theme). The win and game-over dialogs keep their own colours in both
  themes; the dimmed backdrop and their shadows get light-theme values.
- Scrollbars and other browser-drawn parts follow the theme (`color-scheme`).

### Edge cases

- **During a move.** Switching the theme touches no game state: tiles keep animating, a score
  pop in the air keeps fading, the move guard and the 100ms cooldown are not involved, and
  keyboard moves still work while the reveal runs. During the ~0.5s of the reveal the browser
  routes pointer events to the transition overlay, so a mouse click or a swipe that starts in
  that window does nothing; this is accepted.
- **With a dialog open.** The page behind a modal dialog is inert, so the toggle cannot be
  used then. The only way the theme can change under an open dialog is a system-driven change;
  it applies instantly and the dialog, its backdrop and its buttons take the new tokens.
- **Blocked storage.** The switch works for the session and is not remembered.
- **Two tabs.** A change in one tab is not pushed to the other; the next load reads the saved
  choice. (Same as the saved game: last write wins.)

### Unchanged

- Gameplay, input, the saved game, the high score, every dialog's behaviour, the layout at
  every width, and the dark theme's look.
- The favicon keeps its own colours in both themes.

## How it will be checked

- `yarn lint`, `yarn format:check`, `yarn build`, `yarn size`.
- Dark theme pixel-identical to `main` (page and the three dialogs, 1000px and 320px).
- Both themes at 1000px and 320px: header, board with tiles 2 to 32768, every dialog; system
  default with no saved choice (both system settings); a saved choice beats the system; a
  reload keeps the choice; no wrong-theme frame while loading (dev server and production
  preview); the reveal runs and finishes; reduced motion and a browser without
  `startViewTransition` switch at once; storage blocked; a theme switch with a move
  animation and a score pop in flight.
- A search proves no colour literal is left in `src/styles/` outside `theme.css` and
  `tiles.css`.
- Chrome only: Safari and Firefox are not available in the working environment.
