# MY-112 — CI on GitHub Actions, bundle size check, Dependabot, `main` protection

Issue: MY-112 · Branch: `my-112-ci`

CI is a post-push signal, not a merge gate (merges are local, no pull requests —
`ai/decisions/2026-10-10-local-merge-without-pr.md`).

## 1. `@vitejs/plugin-legacy` — measured

Production JS/CSS, gzip -9 (CSS is the same in every option: 1.77 kB):

| Option                                                             | JS served to modern browsers | Extra files                              | Private fields    |
| ------------------------------------------------------------------ | ---------------------------- | ---------------------------------------- | ----------------- |
| Now: plugin with its default modern targets (Chrome 64, Safari 12) | 3.56 kB                      | legacy chunk 2.57 kB + polyfills 12.2 kB | `WeakMap` helpers |
| B: keep plugin, `modernTargets: ['baseline widely available']`     | 2.89 kB                      | same legacy chunk + polyfills            | native            |
| A: remove the plugin (Vite default target)                         | 2.82 kB                      | none                                     | native            |

Correction to what MY-109 reported: of the growth from 1.76 kB to 3.56 kB, about
1.05 kB is simply more code (the OOP classes) and about 0.7 kB is the `WeakMap`
downleveling.

Why B buys nothing: the legacy chunk is only loaded by browsers that fail the
plugin's ES-module detection. Old browsers that pass it (Safari 12–15.3,
Chrome 64–92) would get the modern chunk with native private fields and
`Object.hasOwn` and break anyway. So B keeps all the legacy machinery without
actually covering those browsers.

**Proposal — A:** remove `@vitejs/plugin-legacy`. Vite's default
`build.target` (`baseline-widely-available`: Chrome/Edge 107+, Firefox 104+,
Safari 16+) applies; the game actually runs from Chrome 93 / Safari 15.4. One JS
file, no SystemJS or polyfill chunks, a simpler config, a faster install. Recorded
as a decision; `ai/rules/assets-performance.md`, `AGENTS.md`, and `README.md`
stop mentioning legacy chunks. `terser` stays (the build uses it for
`drop_console`). Autoprefixer keeps using browserslist `defaults`.

## 2. Bundle size check — `size-limit`

- Version: `size-limit` + `@size-limit/file` **12.1** — the latest that fits
  `engines.node` (`^20.19.0 || ^22.13.0 || >=24`); 13+ needs Node 22.18+/22.19+.
- `.size-limit.json`, gzip, two entries: `dist/assets/*.js` and
  `dist/assets/*.css`. Script: `"size": "size-limit"` (runs on an existing
  `dist/`, so CI builds first).
- Limit style — see the open question:
  - **budget (recommended):** JS 8 kB, CSS 4 kB gzip. Room for the planned
    features (dialogs, settings, animations, statistics), so normal feature work
    does not trip it; an accidental heavy dependency or a runaway asset does;
  - **tight:** current size + ~15% (JS 3.3 kB, CSS 2.1 kB); every feature that adds
    code bumps the limit in the same change.

## 3. CI — `.github/workflows/ci.yml`

- Triggers: `push` to any branch (so `main` and branches pushed for a Vercel
  preview both get checked). No `pull_request` trigger — nothing opens pull
  requests.
- `ubuntu-latest`, `actions/checkout@v7`, `actions/setup-node@v7` with
  `node-version: 22` and `cache: yarn`; `HUSKY: 0` so the install does not set up
  git hooks on the runner.
- Steps: `yarn install --frozen-lockfile` → `yarn lint` → `yarn format:check` →
  `yarn build` → `yarn size`.
- Badge at the top of `README.md`.

## 4. Dependabot — dropped (see the author's answers)

- `npm`, weekly: minor and patch updates grouped into one PR; majors one PR each
  (Vite, ESLint majors deserve their own look).
- `github-actions`, weekly, grouped.
- Dependabot PRs run CI; they are merged deliberately (on GitHub or locally), never
  blindly.

## 5. `main` protection — dropped (see the author's answers)

`gh` is not authenticated on this machine, so the author sets it up in GitHub:
Settings → Rules → Rulesets → New branch ruleset → target the default branch →
enable **Restrict deletions** and **Block force pushes**, nothing else (no required
status checks, no required pull requests — they would reject the local-merge
pushes), no bypass list. Step-by-step instructions go into the report.
