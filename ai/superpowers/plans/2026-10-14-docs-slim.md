# MY-138 — Docs without bloat: `ai/map.md` as navigation, a docs rule with limits, no duplicates

Issue: MY-138 · Branch: `my-138-docs-slim` · No spec: no observable behavior changes.

The first task of the «Рефакторинг» milestone: it runs alone and before MY-137 (JS), the CSS refactor and
MY-132 (README), so they edit already short docs. Docs and `.gitattributes` / `.prettierrc` only; nothing in
`src/` changes, so there is no browser check.

## Why

An agent reads about 184 KB of docs before the first line of code; `ai/map.md` alone is 109 KB. Its tables
retell the code (methods, result shapes, formats, constants, measurements) and Prettier pads every table row
to the widest cell. Rules and skills retell each other and the decision records. Nothing states a size limit,
and every task is told to add to the docs and never to cut.

## Author's decisions (2026-10-13, final)

- Do everything, but without fanaticism: docs and decision records were written for a reason. The main
  target is `ai/map.md`; elsewhere cut real duplicates and stale facts only, and keep the substance.
- Decision records are not deleted, consolidated or rewritten. Only the index is regrouped, and a rule for
  the future is added.
- No `browserslist`: the rule that asks for it is reworded.
- `.gitattributes` is deleted and Prettier gets `endOfLine: "auto"`; "LF" mentions go.
- Keep the file name `ai/rules/style.md` and leave room in it for the code conventions of MY-137 and the CSS
  refactor. Do not pre-empt the paths those tasks change (controllers folder, the font file name,
  `animations.css`, the head theme script): keep the docs short so they are cheap to update.
- `README.md` is rewritten by MY-132: only what this task makes wrong is fixed there.

## Rule: nothing important is lost

Everything removed from the map, rules or skills must stay in the code, in a decision record, or in exactly one
remaining doc. A block is moved, not dropped; when unsure, it stays. The final report lists where each
non-trivial block went.

## Changes (one commit each)

1. **`ai/rules/docs.md`** (about 15 lines): the code is the source of "how"; docs say where (map), what must
   hold (rules, skills) and why (decisions); one fact, one home; size limits; a task adds a line or two and
   trims when it crosses a limit; no history in current docs.
2. **`ai/map.md`**: navigation only, about 130–150 lines and at most 12 KB. A list with one line per class
   instead of the tables; a short storage key table; the long recipes go to one place (`ai/skills/feature.md`),
   the link preview recipe to a new skill `ai/skills/og-image.md`; measurements, history and the scripts and
   "Agent docs" tables go (README, `package.json` and `AGENTS.md` have them).
3. **Rules**: `verification.md` merged into `definition-of-done.md`; "File Responsibilities" removed from
   `architecture.md` (the map is its home); stale lines fixed in `scope.md` (tooling is not "planned"),
   `assets-performance.md` (no `browserslist`; it repeated the link preview and font rules) and `oop.md`
   (the head script exception was a fourth copy); the "JS timings match the CSS" line replaced by the
   custom-property rule.
4. **`ai/rules/style.md`, `ai/skills/feature.md`, `ai/skills/review.md`**: moderate trimming. Decision
   rationale and worked histories out, imperatives and the "what must hold" in; `review.md` becomes "walk the
   diff against the DoD and the rules of the touched area" plus what the rules do not cover.
5. **`ai/decisions/README.md`**: index regrouped by topic, one short line per record, order and the stale
   `win-target` title fixed; the rule for the future (a refinement is a new record that restates what stays in
   force, the old one only changes its `Status`; no new "Refined by" notes); narrower "when to add a record".
6. **Entry points**: `CLAUDE.md` is `@AGENTS.md` plus a line or two; `AGENTS.md` gets a shorter "Read First",
   `fonts/` and `public/` in Sources, the `ai/superpowers/` archive line and links to the docs rule;
   `ai/workflow.md`, `ai/prompts/task.md`, `ai/prompts/orchestrator.md` (the «Рефакторинг» milestone after
   «Полировка»), `ai/linear-task-template.md` and `ai/skills/README.md` stop asking to "update everything".
7. **Line endings**: `.gitattributes` removed, `"endOfLine": "auto"` in `.prettierrc`, "LF" mentions removed.
8. **Two short decision records** (added while implementing, per the workflow's "capture decisions as they
   surface"): line endings left to git and Prettier, and no `browserslist`. Both are standing "we do not do X"
   choices of this task; no existing record is touched.

Limits as written in `ai/rules/docs.md` after implementing: a rules file about 150 lines (`style.md` has to hold
the later code conventions), a skill about 12 KB (`feature.md` is the one place for all recipes).
