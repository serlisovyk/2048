# Repo map

Navigation only: where things live and who owns what. How it works is in the code, why in `ai/decisions/`.
Update it when a file, class, storage key or script is added, renamed or removed (`ai/rules/docs.md`).

## Repo

- `src/` — all sources: `index.html`, `favicon.svg`, `fonts/`, `scripts/`, `styles/`.
- `src/fonts/` — the self-hosted Rubik, `rubik.woff2` (Latin, license in its own metadata); update it from Fontsource, keeping the name.
- `public/` — files that need a stable unhashed URL, copied as they are to `dist/`: `og-image.png` and the two crawler files below.
- `public/robots.txt` — allows every crawler; no `Sitemap`, no `Agentmap`.
- `public/llms.txt` — the llmstxt.org summary: an H1, a blockquote, links to the demo, the README, `AGENTS.md` and the repo.
- `assets/` — `demo.gif`, the gameplay GIF shown in `README.md`; not built, not size-checked; remake it when the game's look changes.
- `dist/` — generated by `yarn build`; never edited.
- `webpack.config.js` — re-exports `webpack/config.js`; `webpack/` — the build in parts: paths, CSS browser targets, `parts/`, `plugins/`.
- `vercel.json` — the pinned Vercel build. `eslint.config.js` — flat config; also enforces `ai/rules/oop.md`.
- `.prettierrc` — Prettier options. `.lintstagedrc.json` + `.husky/pre-commit` — ESLint and Prettier on staged files.
- `.size-limit.json` — the budgets: gzip for the JS and CSS bundles, raw bytes for the font.
- `.github/workflows/ci.yml` — CI on every push: lint, format check, build, size.
- `package.json` — scripts (`preview` is `sirv dist`), dev dependencies, `engines.node` (ESLint 10's range; yarn 1 refuses to install outside it).
- `AGENTS.md` — the entry point for agents; `ai/` — agent docs (rules, skills, decisions, prompts).
- `ai/superpowers/` — the archive of past plans and specs: read only the plan or spec of the feature you change.

## Scripts (`src/scripts/`)

Root:

- `main.js` — the composition root: imports the styles, finds the DOM, creates and wires every object, starts them.
- `constants.js` — every shared number and key, and the `SETTING_DEFINITIONS` table.
- `themeHead.js` — plain script, no imports: sets `<html data-theme>` before the first paint; a plugin inlines it. Literals as in `constants.js`.

Model (`game/`) — rules and values; no DOM, storage or timers:

- `Board` — the grid of tiles with ids; slides and merges, and reports a move as `slides` and `merges`.
- `Game` — one game (size, win tile, score, moves, won and over flags); `move()` reports the result; exports and validates its own state.
- `Settings` — the setting values checked against `SETTING_DEFINITIONS`; a setting that `dependsOn` another follows it.
- `Statistics` — the four all-time numbers (played, wins, best score, best tile); counts what it is told.
- `Validation` — `isCount` and `isTile`, the checks `Board`, `Game`, `Statistics` and the records share.

Views (`ui/`) — own their elements and render what they are given; user actions are `on<Action>(handler)`:

- `GridView` — the background cells and the tile elements, the board's accessible name; animates a move from the model's result.
- `ScoreView` — score and high score, the live region, the `+N` pop, the `New record!` badge, the high score reset button.
- `OverlayView` — the win and game-over dialogs and the summary of the game in them.
- `NewGameView` — the New game toolbar button.
- `ConfirmDialogView` — the one reusable "are you sure?" dialog: `ask()` returns a `Promise<boolean>`.
- `SettingsView` — the settings dialog, its toolbar button, the Statistics numbers.
- `ThemeView` — `<html data-theme>`, the toggle button, the `theme-color` metas, the View Transition reveal.
- `FooterView` — writes the current year into the footer.

Input (`input/`) and storage (`storage/`):

- `KeyboardInput` — arrows and WASD by `event.code` → a direction callback.
- `SwipeInput` — a pointer swipe anywhere on the page (one primary pointer, not on a control, not under a dialog) → a direction callback.
- `SafeStorage` — `localStorage` behind an API that never throws; the only code that touches it, bar `themeHead.js`.

Controllers (`controllers/`) — one role each: use cases and flow state:

- `GameController` — the movement guard (`requestMove`), new game, win pause, confirmations. Asks the high score, save and statistics controllers.
- `HighScoreController` — the record of each board size and the New record flag. `GameController` tells it when a game begins and a score changes.
- `SavedGameController` — reads, writes and clears the saved game; owns the version and the upgrade table.
- `SettingsController` — loads, saves (the only writer) and applies the settings; asks before a new game. Talks to `SettingsView`, `GameController`.
- `StatisticsController` — loads and saves the all-time numbers (the only writer); `GameController` reports moves and restarts to it.
- `ThemeController` — the current theme, its saved choice and following the system. Talks to `ThemeView`.

## Styles (`src/styles/`)

`main.css` imports the rest, in this order (`motion.css` stays last):

- `theme.css` — the scales (font sizes, radii, shadow geometry, durations, focus ring) and every UI colour for both themes, the theme reveal.
- `base.css` — `@font-face`, reset, `body` (font, colours, flex column, safe areas, page padding), the focus ring, `.label`, `.visually-hidden`.
- `layout.css` — `.game-layout`, the width the header and the footer share, `--rows-height`, the short landscape layout, the footer.
- `header.css` — the header (logo, score boxes), the score pop, the record badge.
- `board.css` — `.game-container`, the grid and its cell size, the background cells, a tile's structure and animation classes.
- `tiles.css` — the tile palette tokens and one rule per tile value, the fallback rule first.
- `overlays.css` — the `dialog` look, the four dialogs, the backdrop, the summary and statistics blocks.
- `controls.css` — `.button` / `.button-outline`, `.segmented`, the toolbar, `.icon-button`, the GitHub link, the theme toggle's icon swap.
- `animations.css` — every `@keyframes`.
- `motion.css` — the `prefers-reduced-motion` overrides.

## `src/index.html`

- Head: metadata (two `theme-color` metas, Open Graph, Twitter), the theme script (injected by a plugin), favicon, font preload; the entry script is injected by the build.
- Body: `.game-layout` (`.game-header`, `.game-container`, `.site-footer`), then `.github-link`: last in the DOM, the top row by `order`.
- Four modal `<dialog>`s: win (`.win-overlay`), game over (`.game-over`), the confirmation (`.confirm-dialog`) and the settings (`.settings-dialog`).
- The header and footer are as wide as the board, beside it on a short landscape window: `header-toolbar`, `board-fits-the-window`.

## Storage (`STORAGE_KEYS`)

Every access goes through `SafeStorage`; the one exception is `themeHead.js`, which only reads (decision `theme-head-script-html-plugin`).

| Key                                            | Holds                                       | Written by                                   |
| ---------------------------------------------- | ------------------------------------------- | -------------------------------------------- |
| `highScore3x3`, `highScore4x4`, `highScore5x5` | the record of that board size               | `HighScoreController`                        |
| `savedGame`                                    | the game in progress, with a `version`      | `SavedGameController`                        |
| `settings`                                     | the settings, one object with a `version`   | `SettingsController`                         |
| `statistics`                                   | the four all-time numbers, with a `version` | `StatisticsController`                       |
| `theme`                                        | `light` or `dark`, once the toggle was used | `ThemeController` (the head script reads it) |

Formats and versions: the code (`SAVED_GAME_VERSION`, `SETTINGS_VERSION`, `STATISTICS_VERSION`, `SavedGameController`) and the decisions
`saved-game-format`, `board-size-records-and-saved-game`, `win-target-per-board-size` and `statistics` in `ai/decisions/`.

## Where is the recipe

- A game feature, dialog, confirmation, setting or settings section, toolbar button, animation, a save format change: `ai/skills/feature.md`.
- Remaking the link preview image and the favicon: `ai/skills/og-image.md`. Reviewing a diff: `ai/skills/review.md`.
- What must hold: `ai/rules/`. Why it is so: `ai/decisions/` (index in its `README.md`).

## Deployment

Vercel Git integration: `main` is production (<https://2048-xi-three.vercel.app/>), other pushed branches get previews. The build is pinned in `vercel.json`: `yarn build`, output `dist/`.

## Not in this project

- No UI framework, TypeScript, CSS preprocessor or automated tests: decisions `vanilla-js-no-framework`, `no-automated-tests`.
- No pull requests: work merges locally (decision `local-merge-without-pr`).
- No backend, analytics, third-party runtime scripts or font CDN: `ai/rules/scope.md`.
- No undo, seeded random, move history (the move count is not a history), PWA or releases: decision `rejected-features`.
